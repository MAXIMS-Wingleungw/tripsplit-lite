TripSplit Lite 2.1 Collab（即時協同共享版）
=========================================

全新升級：在 V2.0 基礎上加入 Google Firebase / Firestore 免費即時多人同步！
同行朋友只需用手機瀏覽器打開專屬連結或掃描 QR Code，即可即時共同記帳與分帳。
朋友免下載 App、免註冊登入，即開即用，網路正常時改動會自動即時同步！

【旅遊計劃】
- 電腦側邊選單或手機「更多」可開啟「旅遊計劃」，包含「每日行程／想食清單／想買清單」三個分頁。
- 每日行程可新增、修改及刪除：日期、活動名稱必填；時間選填，另有地點、交通方式及備註。
  畫面按日期分組、時間由早至晚排列；同日未定時間項目放在最後，時間以當地計劃時間顯示，不作時區換算。
- 想食／想買清單可記錄名稱、地點或店舖、備註，並勾選／取消完成；未完成項目排在前面。
- 計劃按目前旅程分開儲存，切換旅程不會混用；關閉再開可從同一旅程的旅遊計劃入口查看。
  新建本機旅程的計劃先存於本機，開啟共享時一併上傳；已共享旅程的新增、修改、刪除及完成狀態會即時同步。
- 計劃不會建立帳目、改動付款、退稅、統計或結算；沒有地圖 API 或外部搜尋。
- IndexedDB 升級至版本 3，新增 travelPlans 資料表，保留原本行程與帳目。
  若提示升級被阻擋，請關閉其他舊版 TripSplit 分頁再重新整理。所有同行者需重新載入新版程式。
- JSON 備份含 travelPlans 及 schemaVersion: 3；匯入舊版備份時，計劃清單為空。
  匯入仍沿用原有「取代全部本機資料」行為，請先備份現有資料；舊版程式不支援新計劃資料。
- 更新網站時，請一併更新 js/database.js、js/cloud.js、js/app.js、css/app.css；
  先前退稅功能所需 js/calculations.js 亦應保留最新版。

【旅遊計劃的 Firestore 規則檢查】
- 新增雲端子集合路徑：/shared_trips/{tripId}/travelPlans/{planId}。
  三種項目共用此集合，以 kind 區分 itinerary（每日行程）、food（想食）、shopping（想買）。
- 項目欄位：id、tripId、kind、name、date、time、location、transport、notes、completed、createdAt、updatedAt。
  date/time 為 YYYY-MM-DD／HH:mm 字串；清單或未定時間使用空字串。completed 為布林值，時間戳為 ISO 字串。
- 若正式規則只列出 members、expenses、settlements、rates，必須新增 travelPlans 的對應規則；
  需支援 get/list（下載及即時訂閱）、create/update（新增、修改、勾選完成）、delete（刪除）。
  請沿用既有同行者的授權條件及驗證 tripId 與路徑一致；父行程文件允許存取不代表子集合也自動允許。
  若已有涵蓋所有子集合的遞迴規則，請確認其確實涵蓋此路徑，毋須重複新增。
- 本次未讀取或修改正式 Firestore 規則，亦未部署。不要為此直接開放整個資料庫公開讀寫；
  目前應用程式本身沒有登入流程，若既有規則要求登入，須由網站管理員另行確認授權設計。
- 規則拒絕時會顯示同步異常或儲存失敗；本機已存檔不代表同行者已收到。
  更新規則後可由雲端診斷重新連線，並以兩個裝置實際驗證共享與新增／修改／完成／刪除。

【退稅收款確認】
- 帳目選擇「退稅」後，金額／百分比代表預計退稅，預設顯示「待收退稅」，不會扣減分帳、統計或結算。
- 實際收到後，在「修改帳目」勾選「已收到退稅」，輸入同一帳目幣別的實收金額並儲存。
  結算只扣減實收金額，預計金額仍保留供核對；實收可為零，但不得超過基礎金額。
- 取消勾選並儲存即恢復待收、清除實收金額並重新計算；再次確認時須重新輸入實收。
- 沿用原有付款人「淨代墊」模型：單一付款人會自動調整扣除實收退稅後的淨額；
  多位付款人請核對各自的實際淨代墊（含誰收取退稅），總額須等於扣減後金額才能儲存。
- 例如原額 HK$100、預計退稅 HK$10：待收時計 HK$100；實收 HK$7 確認後計 HK$93。
  兩人均分且一人代墊時，另一人的應還金額依次為 HK$50、HK$46.50。
- 收款狀態、實收與預計金額會隨帳目同步給同行者，亦包含於 JSON 備份匯入／匯出。
- 舊退稅資料沒有收款確認欄位時，一律按待收處理，不會自動視為已收。
  原先已扣預計退稅的分攤會還原，付款人金額按原比例還原（原淨額全零時按付款人均分）。
  畫面會提示核對，請在修改帳目內確認實際付款分配及收款狀態後儲存。
  已記錄還款不會被改寫，結算餘額會按新的收款狀態重新計算。
- 使用此功能時，所有同行者都需載入新版 js/calculations.js 與 js/app.js；
  不要混用舊版網頁編輯共享帳目，以免舊版覆寫確認欄位。

【共享同步與重新開啟修正】
- 修正雲端模組未公開至 window.Cloud，導致自動初始化、編輯上傳及重開後即時訂閱被略過。
- 記住最後開啟或加入的行程；使用同一瀏覽器與網站網址重開時，自動恢復該行程及共享訂閱，不必重新輸入代碼。
- 首次雲端快照也會刷新畫面，並清除離線期間已在雲端刪除的舊資料；本機儲存期間不再忽略其他人的更新。
- 在行程清單分享另一個行程時，只會上傳該行程的資料，不會混入目前開啟的行程。
- 雲端寫入失敗會顯示錯誤，不再當作同步成功；診斷的讀取成功不代表寫入權限或即時訂閱也已成功。
- 部署時請一併更新 js/cloud.js 與 js/app.js，並在瀏覽器重新整理以載入新版程式。

【即時協同共享特色（v2.1.0-Collab）】
1. ☁️ 一鍵發佈雲端共享：
   - 任何本機行程皆可一鍵點擊「☁️ 共享行程」，系統自動將該行程與帳目上傳至 Firestore 雲端資料庫。
   - 自動生成專屬分享連結（URL 帶有 ?trip=TRIP_ID）與專屬行程代碼。
   - 內建手機 QR Code，朋友當面用手機相機一掃即可加入。

2. 🔗 零門檻加入共同編輯：
   - 方式一：朋友點擊分享連結，網頁自動識別並立即載入雲端資料並啟動即時同步。
   - 方式二：在「行程管理」點擊「🔗 輸入代碼加入行程」，貼上行程代碼或連結即可加入。

3. ⚡ Firestore 即時雙向同步：
   - 網路正常且雙方都已開啟同一共享行程時，新增、修改或刪除帳目、成員、匯率、還款或旅遊計劃會自動同步；實際延遲取決於網路及 Firestore 回應。
   - 貼心防干擾機制：若使用者正開啟彈窗輸入帳目，遠端更新會在背後刷新快取，不強制關閉使用者正在輸入的表單。

4. 🛡️ 本地快取與離線優先（Offline-First）：
   - 仍保留 IndexedDB 本機儲存，即使在無網路環境（如飛機上或訊號不佳處），本機資料依然完整無缺。
   - 頂部狀態標籤清楚標記「離線模式」、「本機儲存」或「即時共享中 ☁️」。

5. 🔄 備份檔案 100% 雙向相容：
   - 先前 V1.x、V2.0 匯出的 JSON 備份檔案可 100% 直接在此版本「設定與備份」中匯入還原！

【V2.0 完整核心功能全數保留】
- 精確金額分帳（支援手動輸入前 N-1 人，最後一人自動計算剩餘金額與防呆高亮警告）。
- 附加調整（支援「$ 金額」與「% 百分比」雙模式自動連動）。
- 統計分析頁（所有實際使用幣別分類長條圖與金額彙總、每日每位成員消費總額表）。
- 成員消費詳細頁（成員快速切換、每日消費與代墊明細、每日總額小計）。
- 結算詳情與推導（收支淨額總表、貪婪撮合演算法步驟推導、原始消費清單）。
- 嚴格 IIS CSP 安全設定，不含內聯事件，符合公司網路安全規範。

部署說明
--------------------------
1. 將「TripSplit-Lite-Collab」整個資料夾複製到伺服器目錄或上傳至 GitHub。
2. 在 IIS 中建立站台或應用程式指向此資料夾。
3. 透過電腦或手機瀏覽器開啟即可！

測試說明
--------------------------
1. 原有核心測試：以瀏覽器開啟 tests/test-runner.html。
2. 共享回歸測試（需 Node.js 18 或以上）：在此資料夾執行 node --test .\tests\cloud.test.cjs。
   涵蓋原有計算測試、獨立用戶間的新增/修改/刪除、重開恢復、首次快照、
   表單防干擾、跨行程隔離、共享連結自動加入及雲端失敗處理；
   另包括退稅待收／確認／取消、實收金額、四種分攤、舊資料遷移、結算及備份往返。
   旅遊計劃測試涵蓋三種項目 CRUD、日期時間排序、完成切換、旅程隔離、共享發佈／加入、
   離線刪除恢復、重開、JSON 新舊備份、顯示文字轉義及權限失敗。
3. 自動化共享測試使用模擬 Firestore，不會讀寫正式 Firebase。
   正式部署後仍須以兩個裝置開啟同一行程，確認實際網路、Firebase 規則與同步行為。
